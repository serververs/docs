This guide walks you through setting up a **Serververse™ Network Transit** tunnel on your Linux server. As of **v0.2**, provisioning is token-based — your install command is generated from the dashboard and contains everything needed to configure and bring up the tunnel automatically.

<Warning>
  Ensure you have **out-of-band access (IPMI, VNC, or console)** before proceeding. Misconfigured routing may temporarily break SSH access to your server.
</Warning>

---

## Prerequisites

- A Linux server (VPS, bare metal, container, or homelab)
- Root or `sudo` access
- `curl` or `wget` installed
- A Serververse account with Network Transit access

---

1. Log in to the [Serververse Labs Dashboard](https://labs.serververs.com)

  Your install command is unique to your account and transit IP. Do not share it publicly.

## Step 2 — Run the Installer

SSH into your server and paste the install command from the dashboard. It will look something like:

<CodeGroup>

```bash curl
bash <(curl -fsSL https://api-labs.serververs.com/api/v1/provision/install.sh) --token <YOUR_TOKEN>
```

```bash wget
bash <(wget -qO- https://api-labs.serververs.com/api/v1/provision/install.sh) --token <YOUR_TOKEN>
```

</CodeGroup>

The installer will:

- Validate your provisioning token
- Configure Transit based on your use case
- Bring up the tunnel interface
- Route your allocated public IP through the Serververse network

---

## Step 3 — Verify the Tunnel

Once the installer completes, confirm the tunnel is active:

```bash
# Check the Transit interface is up
ip link show sv-transit

# Confirm your public IP is reachable
curl -4 --interface <YOUR_ROUTED_IP> ip.me
```

Your server's public-facing IP should now match the transit IP shown in your dashboard.

---

## Managing Your Tunnel

You can view all active transit IPs and their status from the **Serververse Dashboard** under **Network Transit → Your IPs**.

---

## Troubleshooting

<AccordionGroup>

<Accordion title="SSH dropped after running the installer">
  This usually means a routing rule has overridden your default gateway. Use out-of-band access (IPMI/VNC/console) to correct the routing table, or restore from a snapshot if available.
</Accordion>

<Accordion title="Public IP is not reachable externally">
  Wait 1–2 minutes for edge provisioning to propagate. If the issue persists, check that the Transit interface is up (`ip link show sv-transit`) and the lookback interface should have the correct ip assigned (`ip link show lo`). Verify your token is valid in the dashboard.
</Accordion>

</AccordionGroup>
