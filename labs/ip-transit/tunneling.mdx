**Serververse™ Network Transit** gives your Linux server a dedicated public IP routed through the Serververse network. Provisioning is token-based: the dashboard generates a single install command that configures and brings up the tunnel for you.

<Warning>
  Make sure you have **out-of-band access** (IPMI, VNC, or a provider console) before you start. A misconfigured route can temporarily cut off SSH.
</Warning>

## Set up your tunnel

<Steps>
  <Step title="Open your tunnel in the dashboard">
    Sign in to the [Serververse Labs Dashboard](https://labs.serververs.com).

    <Frame>
      <img src="/labs/images/labs-login.png" alt="Serververse Labs sign-in page" />
    </Frame>

    Go to **Network Transit**.

    <Frame>
      <img src="/labs/images/labs-overview.png" alt="Network Transit overview" />
    </Frame>

    Your assigned tunnel appears as a card. Click it to open the tunnel details.

    <Frame>
      <img src="/labs/images/labs-peer.png" alt="Assigned tunnel card" />
    </Frame>
  </Step>

  <Step title="Copy your install command">
    The details page shows your public IP, bandwidth usage, and transfer rate. Click **Generate command** to copy the install command to your clipboard.

    <Frame caption="Generate the command">
      <img src="/labs/images/labs-copy-cmd.png" alt="Generate command button" />
    </Frame>

    <Frame caption="Command copied to clipboard">
      <img src="/labs/images/labs-cmd-copied.png" alt="Command copied confirmation" />
    </Frame>

    <Note>
      The command is unique to your account and transit IP. Treat it like a password and don't share it publicly.
    </Note>
  </Step>

  <Step title="Run the installer">
    SSH into your server and paste the command. It looks like this:

    <CodeGroup>
    ```bash curl
    bash <(curl -fsSL https://labs-api.serververs.com/api/v0.3/provision/install.sh) --token <YOUR_TOKEN>
    ```

    ```bash wget
    bash <(wget -qO- https://labs-api.serververs.com/api/v0.3/provision/install.sh) --token <YOUR_TOKEN>
    ```
    </CodeGroup>

    The installer:

    - Validates your provisioning token
    - Configures Transit for your use case
    - Brings up the `sv-transit` tunnel interface
    - Routes your allocated public IP through the Serververse network
    - Installs the [`sv-transit` CLI](#manage-your-tunnel)
  </Step>

  <Step title="Verify the tunnel">
    Check that the interface is up:

    ```bash
    ip link show sv-transit
    ```

    Then confirm traffic leaves through your routed IP:

    ```bash
    curl -4 --interface <YOUR_ROUTED_IP> ip.me
    ```

    <Check>
      The IP returned should match the transit IP shown in your dashboard.
    </Check>
  </Step>
</Steps>

## Manage your tunnel

Manage your tunnel from the **dashboard**, or directly on the server with the **`sv-transit` CLI**.

<Tabs>
  <Tab title="Dashboard">
    View and manage all your tunnels in one place.

    <Steps>
      <Step title="Sign in">
        Open the [Serververse Labs Dashboard](https://labs.serververs.com).
      </Step>
      <Step title="Open Network Transit">
        Go to **Network Transit**.
      </Step>
      <Step title="Select a tunnel">
        Click a tunnel to see its public IP, connection status, and settings.
      </Step>
    </Steps>
  </Tab>

  <Tab title="sv-transit CLI">
    The installer adds `sv-transit` to your server automatically.

    <Note>
      Every command except `version` needs root, so run them with `sudo`. Your provisioning token is the `--token` value in the install command from the dashboard.
    </Note>

    | Command | What it does |
    | --- | --- |
    | `install` | Sets up the tunnel on this machine |
    | `status` | Shows whether the tunnel is up and its last handshake |
    | `migrate` | Replaces an older install with a fresh one |
    | `uninstall` | Removes the tunnel (alias: `remove`) |
    | `version` | Prints the CLI version |

    ### Install

    ```bash
    sudo sv-transit install --token <provisioning-token>
    ```

    For scripted setups, add `--yes` to accept the Terms of Service without a prompt:

    ```bash
    sudo sv-transit install --token <provisioning-token> --yes
    ```

    <Tip>
      `--yes` only skips the Terms of Service prompt. Safety warnings for `migrate` and `uninstall` are always shown.
    </Tip>

    ### Check status

    ```bash
    sudo sv-transit status
    ```

    ### Migrate from an older version

    Stops **every** WireGuard tunnel on the machine, clears `/etc/wireguard`, and runs a fresh install with your token.

    ```bash
    sudo sv-transit migrate --token <provisioning-token>
    ```

    <Warning>
      Migrate deletes **all** WireGuard configs in `/etc/wireguard`, not just Serververse ones. Back up any other tunnels first.

      Don't run it over SSH through the transit IP, or you'll lose access mid-migration. Use the console or another IP.
    </Warning>

    ### Uninstall

    ```bash
    sudo sv-transit uninstall
    ```

    To also remove the `sv-transit` command:

    ```bash
    sudo sv-transit uninstall --purge
    ```

    <Warning>
      Traffic to your public IP stops immediately. Don't run this over a connection that uses the transit IP.
    </Warning>

    ### Version

    ```bash
    sv-transit version
    ```
  </Tab>
</Tabs>

## Troubleshooting

<AccordionGroup>
  <Accordion title="SSH dropped after running the installer" icon="plug-circle-xmark">
    A routing rule has most likely overridden your default gateway. Connect through out-of-band access (IPMI, VNC, or console) and fix the routing table, or restore from a snapshot.
  </Accordion>

  <Accordion title="Public IP isn't reachable externally" icon="globe">
    Edge provisioning can take 1–2 minutes to propagate. If it still fails:

    1. Check the tunnel interface is up: `wg show`
    2. Check the loopback interface has your transit IP: `ip addr show lo`
    3. Confirm your tunnel is still active in the dashboard
  </Accordion>
</AccordionGroup>
