This guide sets up a **Serververse™ Network Transit** tunnel on a self-hosted hypervisor and routes a public subnet to your VMs. The example uses **Proxmox VE**: you create a bridge on the host, the installer attaches your routed subnet to it, and any VM on that bridge gets a public IP.

<Info>
  As of **v0.3**, the install script automatically routes the subnet and assigns it to the Proxmox bridge. Follow every step below in order.
</Info>

<Info>
This routed method is supported only if you have purchased a whole subnet with a minimum size of `/29`. Visit our store to place an order, or open a ticket on our Discord server for guidance.
</Info>

<Warning>
  Make sure you have **out-of-band access** (IPMI, VNC, or console) to the Proxmox host before you start. A misconfigured route on the host can cut off your connection.
</Warning>

## How it works

```text
Internet
   ↓
Serververse Edge Network
   ↓
WireGuard Transit Tunnel (Proxmox host)
   ↓
br-transit bridge  (gateway = first usable IP of your subnet)
   ↓
Your VMs (public IPs from the subnet)
```

## Set up your tunnel

<Steps>
  <Step title="Create the transit bridge">
    On the Proxmox host, edit the network configuration:

    ```bash
    nano /etc/network/interfaces
    ```

    Add this to the **end** of the file:

    ```text
    auto br-transit
    iface br-transit inet static
            bridge-ports none
            bridge-stp off
            bridge-fd 0
            mtu 1420
            post-up echo 1 > /proc/sys/net/ipv4/ip_forward
    ```

    Save the file, then apply the configuration (or reboot the host):

    ```bash
    ifreload -a
    ```

    <Note>
      `bridge-ports none` is intentional. The bridge only carries routed traffic from the tunnel, so it isn't attached to a physical NIC. The MTU of `1420` matches WireGuard overhead.
    </Note>
  </Step>

  <Step title="Open your tunnel in the dashboard">
    Sign in to the [Serververse Labs Dashboard](https://labs.serververs.com).

    <Frame caption="Sign in to the dashboard">
      <img src="/labs/images/ip-transit/dashboard-login.png" alt="Serververse Labs sign-in page" />
    </Frame>

    Go to **Tunnels**.

    <Frame caption="Your tunnels">
      <img src="/labs/images/ip-transit/dashboard-tunnels-list.png" alt="Network Transit tunnels list" />
    </Frame>

    Your assigned subnet tunnel appears as a card. Click it to open the details.

    <Frame caption="Subnet tunnel card">
      <img src="/labs/images/ip-transit/hypervisor-tunnel-card.png" alt="Assigned subnet tunnel card" />
    </Frame>
  </Step>

  <Step title="Copy your install command">
    Click **Generate command** to copy your install command to the clipboard.

    <Frame caption="Generate the command">
      <img src="/labs/images/ip-transit/hypervisor-generate-command.png" alt="Generate command button" />
    </Frame>

    <Frame caption="Command copied to clipboard">
      <img src="/labs/images/ip-transit/hypervisor-command-copied.png" alt="Command copied confirmation" />
    </Frame>

    <Note>
      The command is unique to your account and subnet. Treat it like a password and don't share it publicly.
    </Note>
  </Step>

  <Step title="Run the installer on the Proxmox host">
    Paste the command into the **host shell** (not inside a VM). When it finishes, the output looks like this:

    <Frame caption="Installer output">
      <img src="/labs/images/ip-transit/hypervisor-install-output.png" alt="Installer output for a subnet tunnel" />
    </Frame>

    Note the **bridge IP** (the gateway) and the **usable range** it prints. You'll need both for the VM.
  </Step>

  <Step title="Create the virtual machine">
    1. Create a new VM in the Proxmox web interface.
    2. Under **Hardware**, edit the network device and set the bridge to **`br-transit`**.
    3. Under **Cloud-Init**, set:

    | Setting | Value | Example |
    | --- | --- | --- |
    | **IP Address** | An IP from your subnet, with its prefix length | `91.226.56.10/29` |
    | **Gateway** | The IP attached to the bridge, **not** the VM's own IP | `91.226.56.9` |
    | **User / Password** | A root password so you can SSH in | |

    <Warning>
      The gateway must be the **bridge's** IP. Using the VM's own IP, or an address outside the subnet, leaves the VM without connectivity.
    </Warning>
  </Step>

  <Step title="Verify the IP">
    Start the VM, open its console or SSH in, and run:

    ```bash
    # Confirm the assigned IP and networking
    curl ip.me
    ip a
    ```

    <Frame caption="Expected result">
      <img src="/labs/images/ip-transit/hypervisor-verify-curl.png" alt="curl output showing the routed public IP" />
    </Frame>

    <Check>
      `curl ip.me` should return the IP you assigned to the VM, `ip a` should list it on the VM's network interface, and the VM should now be reachable over SSH from the internet.
    </Check>
  </Step>
</Steps>

## Adding more VMs

Repeat the **Create the virtual machine** step for each VM: same `br-transit` bridge, same gateway, and a different unused IP from your subnet. Don't assign the network, broadcast, or gateway addresses to a VM.

## Managing your tunnel

View all your transit IPs, their status, and usage in the [dashboard](https://labs.serververs.com) under **Tunnels**. To check the tunnel from the host:

```bash
sudo sv-transit status
```

See the [`sv-transit` CLI reference](/labs/ip-transit/tunneling#manage-your-tunnel) for upgrade and removal commands.

<Warning>
  Do not restart the host's networking while the WireGuard tunnel is online. This causes a routing overlap and shuts down WireGuard.
</Warning>
<Info>
  If a networking restart is really needed, use out-of-band access (IPMI, VNC, or console) to the Proxmox host and shut down WireGuard first with `wg-quick down sv-transit`. Then restart the networking.
  Once networking is back online, start WireGuard again with `wg-quick up sv-transit`.
</Info>

## Troubleshooting

<AccordionGroup>
  <Accordion title="VM has no internet access" icon="plug-circle-xmark">
    1. Check the VM's NIC is on `br-transit`.
    2. Check the cloud-init gateway is the **bridge IP**: `ip addr show br-transit` on the host.
    3. Check forwarding is on: `cat /proc/sys/net/ipv4/ip_forward` should print `1`.
    4. Check the tunnel is up: `wg show`.
  </Accordion>

  <Accordion title="Tunnel is up but the IP isn't reachable externally" icon="globe">
    Edge provisioning can take 1–2 minutes to propagate. If it still fails, confirm the tunnel shows as **Online** in the dashboard and that no firewall on the host or VM is blocking inbound traffic.
  </Accordion>

  <Accordion title="Lost access to the host after the installer ran" icon="triangle-exclamation">
    Connect through IPMI, VNC or the console and inspect the routing table with `ip route`. If needed, remove the tunnel with `sudo sv-transit uninstall` and contact us by opening a ticket on Discord.
  </Accordion>

  <Accordion title="VM networking lost after restarting the host networking" icon="triangle-exclamation">
    Use VNC or the Proxmox CLI (for a container: `pct enter <ct-id>`, for a VM: `qm console <vm-id>`) and manually restart networking. If that doesn't help, restarting the VM usually resolves the issue. If it persists, contact us by opening a ticket on Discord.
  </Accordion>
</AccordionGroup>
